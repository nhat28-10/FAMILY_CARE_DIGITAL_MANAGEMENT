# Wearable / Wear OS SOS contract

Updated: 2026-08-07

## Pairing

Backend does not generate a pairing code.

The code displayed by the watch app, for example `FCW-8SRERK`, is the
`deviceIdentifier` sent by mobile FE:

```http
POST /api/v1/families/:familyId/wearables
```

```json
{
  "deviceName": "Wear OS",
  "deviceType": "SMARTWATCH",
  "deviceIdentifier": "FCW-8SRERK"
}
```

`GET /api/v1/wearables/me` only checks whether the current user already has a
paired wearable. If it returns `null`, mobile FE should ask the user for the code
currently shown on the watch.

## Unpair

```http
PATCH /api/v1/families/:familyId/wearables/:deviceId
```

```json
{
  "pairingStatus": "UNPAIRED"
}
```

After a successful PATCH, mobile FE should verify with `GET /api/v1/wearables/me`.

## Sensor event

The watch must be paired before it can send sensor events. Events from an
unpaired device return `WEARABLE_NOT_PAIRED`.

```http
POST /api/v1/families/:familyId/wearables/:deviceId/events
```

Response data:

```json
{
  "event": {
    "id": "sensor-event-id",
    "deviceId": "wearable-device-id",
    "eventType": "HEART_RATE_ABNORMAL",
    "rawValue": {
      "heartRate": 38,
      "thresholdLow": 50,
      "durationSeconds": 30
    },
    "severity": null,
    "detectedAt": "2026-08-07T12:00:00.000Z",
    "createdSosAlertId": null,
    "createdAt": "2026-08-07T12:00:00.000Z"
  },
  "alertId": "sos-alert-id-or-null",
  "alertCreated": true
}
```

If the owner already has an ACTIVE SOS, backend does not create another alert:
`alertCreated=false`, and `alertId` is the existing active SOS id.

## Auto-create SOS rules

- `SOS_BUTTON_PRESSED`: creates SOS.
- `HEART_RATE_ABNORMAL`: creates SOS. Payload supports `heartRate`,
  `thresholdHigh`, `thresholdLow`, and `durationSeconds`.
- `FALL_DETECTED`: creates SOS only when family SOS settings allow auto-create
  from fall detection.
- `HARD_IMPACT`: records event only.
- `ABNORMAL_MOVEMENT`: records event only.

`alert.message` for wearable-created SOS is generated by backend.

## Error codes

Wearable errors include both `code` and `errorCode` in the standard error
envelope:

- `WEARABLE_ALREADY_PAIRED`
- `DEVICE_IDENTIFIER_TAKEN`
- `WEARABLE_NOT_PAIRED`
- `INVALID_SENSOR_EVENT_TYPE`
- `INVALID_SENSOR_EVENT_PAYLOAD`
